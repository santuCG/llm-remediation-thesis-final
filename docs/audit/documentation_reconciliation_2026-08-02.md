# Documentation Reconciliation Against Frozen Evidence (2026-08-02)

**Trigger.** After the reproducibility audit regenerated baselines and changed pipeline behaviour, several methodology-documentation claims were questioned against the frozen evidence (repo tag `thesis-freeze-2026-08-02`, commit `5a227c8f`). This report cross-checks every questioned claim against primary evidence and classifies each as **CONFIRMED**, **CORRECTED** (an inaccuracy fixed in this pass), or **SCOPED** (true but needed clearer scoping). Corrections applied to the frozen docs are recorded as post-freeze documentation fixes.

Method: repository is the source of truth. Every claim below is checked against files under `results/`, `.github/workflows/`, and the recorded CI provenance.

## Finding 1 — The `EOVERRIDE` observation is REAL and is directly evidenced (CONFIRMED, and strengthened)

The core of Stage 6 (`docs/04-experimental-methodology.md`) and Observation 3 (`docs/05-results-and-discussion.md`) is correct and, better, is evidenced in the *final frozen 18-scenario dataset* — not only in "initial experiments."

- **Evidence.** `results/execution_evidence/JS-05/llm-request.json` and `.../llm-response.json` record: an override of the **direct** dependency `jsonwebtoken@0.4.0` to `4.2.2` failed with `npm ... code EOVERRIDE ... Override for jsonwebtoken@0.4.0 conflicts with direct dependency`. This was fed into the retry; the LLM reasoned about it and switched to a direct upgrade.
- **Outcome (FACT, `results/execution_evidence/JS-05/metrics.json`):** final `strategy = direct_upgrade`, version `4.2.2`, `retry_count = 1`, `rescan_success = true` (baseline 383 → rescan 187 matches).
- **JS-08** similarly references `EOVERRIDE` in its LLM I/O and completes with `retry_count = 1`, `rescan_success = true`.

**Disposition: CONFIRMED.** The `EOVERRIDE` constraint and the constraint-aware adaptation are genuine. **Action for the thesis:** JS-05 should be added as a case study, because it is direct evidence of the constraint-aware retry loop working — currently under-used.

**Scoping note:** `EOVERRIDE` appears only in the LLM request/response JSON (as retry context and reasoning). It does **not** appear in any `build.log`, and it is not the failure mode of the *deterministic* baseline (see Finding 3).

## Finding 2 — "npm v11" is inaccurate for the frozen dataset's environment (CORRECTED)

`docs/04-experimental-methodology.md:200` stated: *"npm v11 prevents overrides from replacing an existing direct dependency…"*

- **Evidence.** Both workflows pin **Node.js 18.x** (`.github/workflows/generic-remediation.yml:49`, `grype-baseline.yml:48`); `docs/02-experimental-environment.md:14–15` lists Node 18.x / npm 9.x. Node 18.x ships npm ~9–10, **not v11**. The frozen 18-scenario evidence carries GitHub Actions run identifiers (`experiment_manifest.json`), confirming it was generated by CI on node 18.x.
- The "npm v11" figure is consistent with a **local** environment (Node v24.18.0 → npm 11.x), which `docs/02:24` separately references (see Finding 5).

**Disposition: CORRECTED.** The `EOVERRIDE` *behaviour* is real (npm `overrides` has enforced this since npm 8.3), but attributing it specifically to "npm v11" is inconsistent with the environment that produced the frozen evidence. The specific version is removed and the observation is scoped to the initial local exploration.

## Finding 3 — Deterministic-npm-failure cause was mis-attributed to `ERESOLVE`/shadowing (CORRECTED)

`docs/01-overview.md:100` (a sentence added during the Phase 9 audit) stated the npm deterministic baseline fails *"because dependency shadowing and `ERESOLVE`/`EOVERRIDE` constraints leave the vulnerable version nested in the graph despite a nominally successful install."*

- **Evidence.** `ERESOLVE` appears in **no** file under `results/`. The deterministic baseline for all nine npm scenarios recorded `build_success = false` and **did not reach the rescan stage** (`results/reproducibility_verification/JS-0*/metrics.json`; no `rescan.json` present). The recorded failure mode is the **application build** (a pre-existing TypeScript `tsc` toolchain incompatibility), not a dependency-resolution error, and not a "nominally successful install" that left the vulnerability nested.
- **Ownership.** This phrasing was introduced by the reviewer during the Phase 9 A1 fix; it over-attributed the cause and is corrected here.

**Disposition: CORRECTED.** The accurate statement: the deterministic npm baseline did **not achieve a validated remediation**, because it failed at the application build stage before a post-remediation scan could confirm any fix. Nested-resolution constraints (e.g. `EOVERRIDE`) are the conceptual reason transitive npm fixes are hard and were observed *in the LLM pipeline* (Finding 1), not in the deterministic baseline's recorded failure.

## Finding 4 — "The experiment was halted without further validation" needs scoping (SCOPED)

`docs/04:198` and `docs/02:268` state the experiment was "halted" on `EOVERRIDE`.

- **Evidence.** This is true of the **initial development experiments** (pre-CI, local), which is how `docs/04` frames it ("During the initial experiments"). It is **not** true of the final frozen runs: JS-05 and JS-08 hit `EOVERRIDE`, fed it into the retry, and completed to `rescan_success = true` (Finding 1). `docs/02:268` states "halted" without the "initial" qualifier and could mislead an examiner into thinking scenarios were left unvalidated.

**Disposition: SCOPED.** Clarify that the halt applied to the initial exploration, and that the final constraint-aware pipeline (with the single retry) completed and validated these scenarios.

## Finding 5 — `docs/02` conflates two environments (CORRECTED)

`docs/02-experimental-environment.md` lists Node 18.x / npm 9.x (lines 14–15) but then notes "The Node.js version (v24.18.0)…" with `EBADENGINE` warnings (line 24).

- **Evidence.** The frozen dataset was generated by CI on Node 18.x (Finding 2). `v24.18.0` is a local exploratory environment (the machine used for manual reproduction; it also produced the npm 11 figure in Finding 2). Presenting both as "the environment" is internally inconsistent.

**Disposition: CORRECTED.** Clarify that Node 18.x is the CI experiment environment that produced the frozen dataset, and that `v24.18.0` refers to local exploratory runs.
